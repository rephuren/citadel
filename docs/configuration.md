# Справочник по конфигурации

Файл конфигурации это JSON с двумя разделами: `servers` (что подключать) и `policy` (по каким правилам пускать вызовы). Все поля политики необязательны: без них шлюз только даёт пространства имён, лимиты и журнал.

## servers

```json
"servers": {
  "notes": { "command": "node", "args": ["server.js"], "env": { "KEY": "value" }, "trust": "trusted", "inheritEnv": false, "cwd": "." }
}
```

| поле | значение |
| :-- | :-- |
| ключ | имя сервера: латиница, цифры и дефис, до 32 символов. Из него строятся имена инструментов `имя__инструмент` |
| `command`, `args` | как запустить сервер по stdio |
| `env` | переменные окружения сервера |
| `inheritEnv` | по умолчанию `false`: серверу выдаются только `PATH`, `HOME` и ещё несколько безобидных переменных плюс то, что указано в `env`. Ключи и токены из вашего окружения ему не попадут |
| `trust` | `trusted` (по умолчанию) или `untrusted`: всё, что вернул недоверенный сервер, помечается как заражённое |

## policy

| поле | значение по умолчанию | что делает |
| :-- | :-- | :-- |
| `default` | `allow` | действие для инструментов, к которым не подошло ни одно правило: `allow`, `deny`, `confirm` |
| `rules` | `[]` | список правил, см. ниже |
| `taint.mode` | `off` | `off`, `log` (только записывать), `trifecta` (запретить отправку наружу при приватных данных и недоверенном контенте в одной сессии), `strict` (запретить отправку наружу после любого недоверенного контента) |
| `taint.onViolation` | `deny` | `deny` или `confirm` (потребовать подтверждение человека) |
| `limits.maxResultBytes` | 262144 | результат больше этого не доходит до модели |
| `limits.maxArgsBytes` | 65536 | аргументы больше этого отклоняются |
| `limits.callsPerMinute` | 600 | общий лимит вызовов в минуту |
| `limits.timeoutMs` | 30000 | таймаут ответа сервера |
| `sanitize.stripInvisible` | `false` | убирать невидимые символы и Unicode-теги из определений и результатов |
| `sanitize.blockDefinitionsAt` | `off` | скрывать инструменты, у которых находки не ниже этого уровня (`critical`, `high`, `medium`). Правила про возможности (BSK005–007) сами по себе не скрывают |
| `sanitize.scanResults` | `off` | искать инъекции в результатах: `log`, `annotate` (добавить предупреждение), `block` (скрыть результат) |
| `sanitize.pinFile` | нет | файл закрепления (`citadel pin`): изменённый или новый инструмент скрывается |
| `audit.file` | нет | журнал аудита (JSON по строке на событие) |
| `approvals.file` | нет | хранилище подтверждений; без него `confirm` равносильно запрету |

### Правила

```json
{ "match": "files__read_file", "action": "allow", "labels": ["private"], "callsPerMinute": 20,
  "args": { "path": { "pattern": "^[A-Za-z0-9_./-]+$", "forbid": [".."], "maxLength": 120, "enum": ["a", "b"] } } }
```

- `match`: имя `сервер__инструмент`, `*` заменяет любую последовательность символов. Действие берётся из первого подходящего правила, у которого оно задано, а ограничения аргументов и метки собираются со всех подходящих.
- `labels`: `private` (отдаёт приватные данные), `untrusted` (отдаёт недоверенный контент), `sink` (отправляет данные наружу).
- `args`: ограничения аргументов. Нарушение даёт отказ, который видит модель.

## Подтверждения

Когда вызов требует человека, шлюз возвращает модели отказ с номером. Человек выполняет `citadel approve <номер> --config citadel.json`, после чего та же попытка с теми же аргументами проходит **один раз**. Модель одобрить сама себя не может: файл подтверждений она не видит. Заявка живёт 10 минут.

## Что шлюз не делает

- Только инструменты (`tools`). Запросы `resources/*`, `prompts/*`, а также `sampling`, `roots` и `elicitation` со стороны серверов отклоняются.
- Только серверы по stdio. Удалённые серверы по HTTP не поддерживаются.
- Это не песочница: сервер выполняется с правами вашего пользователя. Шлюз ограничивает то, что проходит между агентом и сервером, но не изолирует процесс сервера от системы.
